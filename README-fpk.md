# 飞牛 fpk 安装说明

## 产物

`cfopt.fpk`（约 48 KB）—— 标准 tar.gz 结构，与飞牛 `fnpack` 产物一致。

## 2.4.0 更新

- 新增 **Cloudflare Tunnel 加速**：给跑在 NAS 上的 cloudflared 用的隧道边缘优选
- 隧道连接器不走普通边缘，只连 `region1/region2.v2.argotunnel.com` 的
  **7844** 端口（HTTP/2 + QUIC），对应专用段 `198.41.192.0/24`、`198.41.200.0/24`；
  这两段不是 anycast，同段不同 IP 会落到不同机房（实测 LAX 与 SJC 混在同一 /24），
  所以逐 IP 全量实测 508 个，不做抽样
- 排序以 7844 端口TCP握手为准（隧道真正走的通道），再顺序复测 3 次取中位数；
  机房只从 443 的 CF-RAY 读出来用于界面解释
- region1 下发最快的 N 个、region2 下发次快的 N 个，保留备份边缘
- 应用内独立 DNS 服务监听 `:15353`（`TUNNEL_DNS_LISTEN` 可改），
  **不改 NAS 系统 DNS、不影响 hosts 模式**；SRV 等其它记录原样转发上游
- 面板直接给出可粘贴的 `TUNNEL_DNS_RESOLVER_ADDRS=<NAS_IP>:15353`
  Compose 片段和 `--dns-resolver-addrs` 命令参数
- 安全性：隧道扫描失败或结果超过 3 天时自动退回上游解析，
  最坏情况只是没有提速，不会出现隧道连不上
- 说明范围：优化的是「边缘 → 本机 cloudflared」这一跳（决定隧道上传/下载速度）；
  「访问者 → 边缘」那一跳由访问者自己的 DNS 决定，本机改不了

## 2.3.2 更新

- 机房从硬限制改为偏好：其他机房比偏好机房快 20ms 以上时自动采用，
  解决 NAS 出口把 HKG 绕到 156ms、却仍被迫使用 HKG 的问题
- 机房分布直接标注各机房本轮最快延迟，例如 `HKG 8 · 156ms`、`SJC 51 · 30ms`
- 自动切换后立即把实际机房写入网段缓存，下一轮仍走快速扫描，不再全量
- 复用同一个 SSLContext，避免每个探测线程重复加载系统 CA（NAS 上尤其明显）

## 2.3.1 更新

- 修复域名一直停在「排队中」：启动时不再同步扫第一个域名，
  所有到期域名交给后台调度器，排队状态一变化页面自动刷新
- 同一时间只扫描一个域名。每个扫描本身就有上百个探测线程，
  两个域名同时跑会互相抢连接，实测会把快速扫描整批拖到超时
- 快速扫描改为 32 个线程，失败后先用 16 线程重试一次，
  不再因为一次抖动就直接回退到 11942 个 IP 的全量扫描
- 全量探测超时从 4 秒降到 3 秒，单轮全量约快 25%，后面的域名少等一会儿
- 仍然保留 v2too 三网优选源和顺序 3 次复测取中位数

## 2.3.0 更新

- 扫描时自动合并 [ip.v2too.top](https://ip.v2too.top/) 的三网优选列表
  （`?carrier=ct|cm|cu`，约 30 个 IP）作为额外候选
- 只取 IP，不采用站点的延迟/速度标签：仍由本机实测决定机房、延迟和排序
- 列表缓存 15 分钟；接口不可达时自动跳过，不影响正常扫描
- 实测这 30 个 IP 里有 14 个在本机落到 HKG，握手 45–66ms，
  正好补上内置网段抽样扫不到 HKG 的短板
- 合并后仍然是同一套逻辑：机房匹配 → 延迟上限 → 顺序复测 → 择优下发

## 2.2.2 更新

- 修复测速偏高：120 线程并发扫描会把握手耗时读数放大好几倍
  （实测同一 HKG 节点并发报 594ms，顺序复测只有 111ms）
- 候选节点改为顺序复测 3 次纯 TCP 握手、取中位数，不再保留并发读数，
  也不再取"两次里更慢的一次"
- 目标机房和降级机房各自最快的节点都会纳入复测，不会被总榜埋没
- 效果：HKG 节点恢复到真实的 48–100ms 区间，≤200ms 上限不再误杀快节点
- 候选表的延迟对比条按当前展示的 20 个节点缩放，不会因尾部高延迟节点被压扁

## 2.2.1 更新

- 新增「延迟上限」：默认只下发 ≤200ms 的节点，超过的节点自动剔除
- 面板添加域名时可选上限，卡片「设置」里可随时调整（100–3000ms，或设为不限）
- 调小上限立即生效：当前高于上限的节点马上停止下发，再后台按新条件重扫
- 上限内一个节点都没有时清空下发并提示最快延迟，不会继续用高延迟 IP
- 国内网络访问 CF 常见的 200ms+ 节点（如部分 LAX/AMS 落地）不会再被选中
- 新增「全量」扫描按钮：快速扫描只抽样缓存网段，怀疑漏掉更快节点时可强制重扫全部网段
- 卡片显示「缓存 N 段 / 下轮全量」，右上角显示版本号，升级是否生效一目了然

## 2.2.0 更新

- 目标机房一个节点都扫不到时，自动降级到实际可用的机房（如 HKG → SIN/NRT），
  域名不再直接变成"未接入"，面板会提示并支持一键采用这些机房
- 卡片新增「设置」，可在面板里改机房、下发节点数、扫描周期
- 拒绝通配符域名（`*.example.com` 做 TLS SNI 会被 CF 拒绝，永远扫不到结果）
- 删除/停用域名后，`/etc/hosts` 的标记区块会在一轮内自动清理
- 快速扫描整段不可达时自动回退全量扫描
- 页面动态内容统一转义，修复存储型 XSS

## 为什么不用 Docker 了

上一版是 Docker 方案，安装时会去拉 `python:3.12-slim`。你的环境里
`registry-1.docker.io` 不可达，导致：

```
Error response from daemon: Get "https://registry-1.docker.io/v2/":
net/http: request canceled while waiting for connection
```

**这一版改成原生 Python 运行**：代码是纯标准库（零第三方依赖），
manifest 里声明 `install_dep_apps=python312`，飞牛会自动装好 Python 运行时。

结果：**不需要 Docker，不需要拉任何镜像，安装即用。**

## 安装

1. 应用中心 → 手动安装 → 选 `cfopt.fpk`
2. 或命令行：`appcenter-cli install /path/to/cfopt.fpk`

安装过程只做两件事：建数据目录、检查 Python 运行时。秒级完成。

## 使用

装好后飞牛OS 桌面出现「Cloudflare 优选」图标，点开即管理面板。
也可直接访问 `http://飞牛OS的IP:8080/`。

流程：填域名 → 点「添加并扫描」→ 自动优选 → 自动写入 `/etc/hosts`。

## 目录说明

| 路径 | 用途 |
|---|---|
| `/var/apps/cfopt/var` | 域名配置、扫描结果、运行日志 `cfopt.log` |
| `/etc/hosts` | 优选结果写入这里（标记区块 `cfopt-managed`） |

卸载时自动清理 hosts 区块，并备份到 `/etc/hosts.cfopt.bak`。

## 排查

服务起不来时看日志：

```bash
tail -50 /var/apps/cfopt/var/cfopt.log
```

手动重启：

```bash
/var/apps/cfopt/cmd/main stop
/var/apps/cfopt/cmd/main start
/var/apps/cfopt/cmd/main status   # 0=运行中 3=未运行
```

## 权限说明

`config/privilege` 设为 `run-as: root`。这是必需的：写入 `/etc/hosts`
需要 root 权限。官方文档建议尽量用 package 用户，但本应用的**核心功能**
就是改 hosts，没有更窄的方案。

## 重新打包

```bash
# 源码就在 app/src，改完直接打包
cd <这个目录>
fnpack build

# 产物
ls -lh cfopt.fpk
```

## 已知限制

- **只影响飞牛OS 本机**：写的是宿主机 `/etc/hosts`，其他设备不受影响
- 需要 `python312` 运行时（manifest 已声明，飞牛自动安装）
- 域名必须已托管到 Cloudflare 且开启小黄云，否则添加时会被拒绝
